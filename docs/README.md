# Documentation

## Getting started

- [`install.md`](install.md): install the `schem` CLI and configure the 12-tool MCP server for Claude Code, Claude Desktop, Cursor, VS Code and Codex CLI.
- [`dsl.md`](dsl.md): write `.schem` text schematics, run CLI commands and read diagnostics.
- [`../examples/`](../examples/): 12 examples (8 JSON and 4 `.schem` text files).
- [`../skills/schem/SKILL.md`](../skills/schem/SKILL.md): agent skill covering all 12 MCP tools, the CLI workflow and `.schem` syntax.

## Reference guides

- [`netlist-format.md`](netlist-format.md): how to write a `.schem.json` circuit file by hand.
- [`parts.md`](parts.md): every part type and its pin names (generated by `npm run docs:parts`).
- [`templates.md`](templates.md): the circuits schem recognises and draws in their textbook shape (op-amp stages, active filters, oscillators, H-bridges, I2C buses and more).
- [`editing.md`](editing.md): how to change a `.schem` or `.schem.json` circuit with `schem edit` without reshuffling its drawing.
- [`themes.md`](themes.md): rendering themes (`clean`, `dark`, `blueprint`, `textbook`, `mono-print`) and transparent backgrounds.
- [`spice-import.md`](spice-import.md): import SPICE netlists (`.cir`, `.sp`, `.net`) via CLI, MCP or TypeScript.

## Architecture & benchmarks

- [`../SPEC.md`](../SPEC.md): the full design (data model, symbols, layout engine, verifier, phases and gates).
- [`verification-stack.html`](verification-stack.html): the layers that check a drawing, from "shows exactly the netlist" up to blind rating. Open it in a browser.
- [`general-layout.md`](general-layout.md): how circuits with no template are drawn (supply symbols, vertical stacks, flow, pin order), the benchmark that measures it (`npm run bench`), and the open jobs. Start here if you want to improve drawings.
- [`showcase/`](showcase/): the comparison with tscircuit, SKiDL, netlistsvg and schemdraw (`npm run showcase` rebuilds it). The baselines and their attempt log are in [`../baselines/`](../baselines/).

Build notes and reviews, kept for anyone who wants to know why things are the way they are. They describe the code at the date they were written.

- [`PHASE0A-NOTES.md`](PHASE0A-NOTES.md) and [`PHASE0B-NOTES.md`](PHASE0B-NOTES.md): build notes per phase, including the gate results.
- [`PROJECT-AUDIT-2026-10-25.md`](PROJECT-AUDIT-2026-10-25.md) and [`PHASE0B-PROGRESS-2026-10-25.md`](PHASE0B-PROGRESS-2026-10-25.md): an audit against the spec and the work that followed it.
- [`agent-briefs/`](agent-briefs/) and [`agent-reports/`](agent-reports/): tasks given to coding agents and their reports. Several parts of this project were built by AI coding agents working from these briefs, with every result reviewed.
- [`../archive/`](../archive/): earlier spec revisions, their reviews, and the original plan page.
