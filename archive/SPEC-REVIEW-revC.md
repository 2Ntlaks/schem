## 1. Comments

| Label | Section | Issue (counterexample) | Proposed change |
|---|---|---|---|
| blocker for 0a | 6.2, 7.3, 9.3, 9.7 | The spec does not define whether "in a net" means the physical terminal or its class. ESP32 group gnd = {14, 29, 38}, net GND = [U1{GND}, B1[-]]. Under the physical reading, pins 29 and 38 are hidden, and each one gets a "ground pin in no net" warning. Under the class reading they must be drawn, and hiding them makes 9.7 invalid. Case 5 (in 0a) depends on which reading is used. Also, `nc U1[14]` is allowed on a group member, but 14 is the representative: 9.7 then requires pin 14 to be both "attached" and "nothing attached", so the drawing is always invalid. | Define "in a net" per physical terminal, as written. Use classes only for invariants 1-2, merges and the 9.7 comparison. Representative = lowest-numbered member that is not NC (a group with no such member cannot be an endpoint: validation error). No supply warning for an unwritten member whose group is connected. `connect` on a member whose class is already in a net merges by class. |
| blocker for 0a | 9.7 | Drawings that are electrically wrong still pass. (a) "Terminals in no net that are drawn must have nothing attached (warning, not invalid)": read literally, a net-X wire on a drawn spare pin U1[5] is only a warning. (b) Only partitions are compared: if a `5V` net is drawn entirely with ports whose text is "3V3", the partition is identical, so the drawing is valid but shows the wrong voltage. The same applies to a ground symbol on a power net. (c) The table has no row for no-connect marks. The default ground has empty visible text, so if NC marks are keyed like ports, every NC pin joins the ground virtual net. (d) Two pin anchors of different nets at the same point (6,0) with no conductor match no row, and union-find never joins them. (e) There is no rule that conductors are axis-aligned. | Attached-to-unconnected-pin = invalid. Each virtual group's text, domain mark and symbol class must equal its circuit net's name, domain and kind. Virtual key = (symbol class, text, domain). Add rows: NC mark at a bare pin anchor = NC, anywhere else or with a conductor = invalid; coincident pin anchors = invalid; non-orthogonal conductor = invalid. Add each case to the 0a suite. |
| blocker for 0a | 7.1, 9.1 rule 4, 9.2 step 7 | The router's forbidden set and validity rule 4 disagree. Verifier side: rule 4 says "inside", so a foreign wire (2,0)-(8,0) lying on an IC box's top edge (artwork and keep-out boundary both at y=0) passes, and so does a wire through a ground symbol's bar (port keep-outs are not mentioned). Router side: it ignores label and port envelopes, so for R1's label (envelope y 7.8-9.2) it will route a wire along y=8, which rule 4 rejects. 0a has no repair step to recover. 7.1 only claims "pin anchors lie on its boundary" and nothing enforces it. LED arrows that extend past pin 2 put pin 2 inside the keep-out, and a pin on the top boundary with `dir: left` has its approach point on the boundary, so it is forbidden and can never be reached. | Write one forbidden-geometry definition in `geom`: part and port keep-outs and rounded label envelopes, inside or on the boundary, except each pin's own anchor and its approach along `dir`. The router uses it; the verifier re-checks it on the render model. Loader rule: every anchor is on the keep-out boundary, and anchor + `dir` is strictly outside it. |
| blocker for 0a | 9.2 steps 2-6, 15 | (a) No step chooses orientations for parts outside templates, but every offset in the solve depends on orientation, and 0a has no templates. (b) The inter-column gap is a constant. Keep-out boundaries are forbidden, so a 2 G gap leaves exactly one free track. In case 5, SDA and SCL both jog between U1's column and the next at overlapping y, and the second net has no track. The least solution puts every block at the top of its column, so jogs are the norm, not the exception. "Spacing +1 G" (repair) is not in 0a. (c) The 0a build list omits steps 2, 3 and 7b, yet uses ranks and the suite tests ports. | Define default orientations (two-pin part between a rail and another net: vertical; otherwise along the flow; sources + up; ICs rot 0). Set each channel's width to the number of tracks it needs (an interval count over the ordered nets, as in left-edge channel routing) + 2. Put steps 2 and 3 (and either 7b or "ports only at pins") into the 0a list, or say that 0a draws every net as a wire. |
| fix before 0b | 6.4, 9.2 step 6 | The difference-constraint direction is stated correctly (a-b≥c gives edge b→a of weight c, longest path, and a positive cycle means infeasible). But constraints from ordering, bands and rigid regions have no priority. Lock A x=10, lock B x=12, ranks put B in the earlier column: the cycle {lock A, lock B, B-before-A} is not lock-only, so the rule drops the "lowest", i.e. the column constraint. A and B then overlap. Locks also need an origin variable x0 (x_A - x0 = 10), and nothing says what status results once the drop bound is reached. | Structural separation constraints are never dropped. Feed locks and x/y relative hints into ordering (sort locked blocks by their x). If a cycle contains structural constraints, re-order once, then `infeasible`. Name the x0 node and its zero-weight edges. Bound reached → `budget_exhausted`. |
| fix before 0b | 9.2 step 6 | The least (most compact) solution puts every variable at its minimum. Nothing makes connected pins line up, so rule 11 straight series lines happen only by accident. | Run a second pass on the same constraint graph that minimises Σ w·|Δ| between connected pin coordinates (network simplex, Gansner et al. 1993) or applies Brandes-Köpf-style alignment. Keep the least solution as the fallback. |

## 3. Verdict

The data model, merge rules and conductor normalisation hold up against attack. The verifier's contact table and the router's forbidden set do not.
There are four 0a blockers. All are definitional, about one paragraph each: group membership, verifier name/NC/attachment rules, one shared forbidden-geometry rule, and orientation plus channel sizing.
Fix those four, then start 0a. Appendix A must be corrected before templates are built in 0b.
