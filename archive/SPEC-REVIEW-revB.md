# SPEC review: rev B

## 1. Verdict

Not ready to start Phase 0 **as specified**: its correctness oracle has counterexamples, and its workload is closer to a first engine implementation than a spike.
1. Define physical pin-group equivalence and a complete, segmentation-independent verifier contract.
2. Specify terminal escape geometry and how constrained regions become feasible placed blocks.
3. Freeze concrete test inputs/edits, separate confidence from validity, and narrow the initial bake-off before applying its gates.

## 3. New findings

Counterexamples are consequences of the written rules, not observations of a nonexistent engine. V1-V7 below provide checks and sources.

| ID | Severity | Section | Issue | Why it matters | Proposed change |
|---|---|---|---|---|---|
| N01 | blocker | 6.2-6.3, 9.7 | Group identity and physical terminal identity are conflated. | `n1=[U1{gnd},R1[1]]`, `n2=[U1[14],R2[1]]` passes uniqueness over canonical strings although the group contains pin 14. Two numbered members of the same internal group can also be assigned different nets. Group expansion can erase which header terminal was actually used (V1). | Keep selected physical terminals as endpoints; maintain a separate internal electrical-equivalence relation. Validate membership and NC rules over that relation, while defining NC as “no external connection” for a numbered terminal. Make group shorthand explicitly logical, with a deterministic representative and disclosure that no particular physical terminal was selected. |
| N02 | blocker | 7.1, 9.1-9.2 | Routing obstacles include symbol leads and half-stroke expansion, with no terminal exception. | The resistor's pin at `(0,0)` is inside its expanded artwork envelope; any wire reaching it crosses that envelope. Blocking all cells touched by it can make even case 1 unroutable (V1). | Define per-pin escape corridors in `dir`, permitted own-pin contact, stroke clearances and fractional-envelope rasterization. Keep foreign pins blocked. Test the terminal rules before evaluating placement quality. |
| N03 | blocker | 9.2 steps 1, 4-6, 9.4 | A region starts as constraints and becomes a rigid block without a specified step that solves its interior. | A feedback resistor has fixed length but is told to span two op-amp columns; a wider label changes required spacing. A locked child may conflict with the region's proposed translation. Pushing whole blocks right/down cannot solve internal alignment or choose label sides. | Define region inputs/outputs: local feasible geometry, label anchors, boundary ports and envelope. Implement a small deterministic internal constraint procedure, then global ordering/legalization. State how child locks restrict placement, when a template is abandoned, and which infeasibilities are proven versus merely not found. |
| N04 | blocker | 9.7 rules 3-4 | The verifier trusts visibility and requires every drawn pin to have a wire or port. | A renderer can omit a connected pin and have it excluded from both sides of the comparison. Conversely, an intentional NC mark or an allowed dangling pin fails rule 4 despite being valid circuit input (V1). | Derive the expected terminal inventory from circuit/assets, independently of layout visibility. Require every connected terminal to be represented directly or by an explicit group/virtual mapping. Define separate connected, NC and unconnected states, with NC marks checked against the circuit and dangling pins remaining electrical warnings. |
| N05 | blocker | 9.7 rules 1-2 | Connectivity depends on segment decomposition; virtual connections lack a complete visual contract. | A dotless T is disconnected when its trunk is one segment but connected when that same trunk is split at the tap. A similarly split dotless X can falsely short two nets. Same-name joining is undefined for unnamed power nets and does not itself prove a label/port visibly attaches to a wire (V1). | Normalize conductor geometry and classify each contact by incident directions, pin attachment and explicit dot, independently of serialization. Define collinear overlaps, T/X rules, dot degree and dangling fragments. Give virtual terminals explicit anchors and visible, unambiguous names/domain notation; verify what is drawn rather than trusting route net tags. |
| N06 | should fix | 6.3, 11.3 | Merge rules do not cover the input space and cannot represent intentional relabeling safely. | Two unnamed nets have no stated survivor; merging signal with ground has no stated resulting kind/domain. Two separately entered portions of the same supply cannot be consolidated if every pair of different power nets is forbidden. JSON loads can bypass edit-only checks. | Define deterministic N-way merges, survivor choice, kind/domain propagation and equivalent-net handling, using one validator for loads and edits. Keep suspicious merges blocked by default but permit an explicit, checked consolidation of the same supply; distinguish that from connecting incompatible supplies. |
| N07 | should fix | 6.4, 9.2 | Cycle detection is specified on relations rather than normalized constraints. | `A right-of B` and `B above A` form a relation cycle but are jointly feasible. `near` is symmetric. Aligning centres of differently sized parts can be impossible on the integer grid. Normal hints “beat templates” but only high/strict conflicts explicitly disable them. | Normalize x/y inequalities and equalities separately, treat proximity as a soft cost, and define integer feasibility and precedence including locks. Return a sufficient conflicting subset; do not require the globally smallest set. |
| N08 | should fix | 6.5, 9.6, 10.1, 13 | Persistent IDs, canonical equivalence and history fingerprints remain mixed. | Reversing DSL connection declarations assigns different net IDs and hence routing order. Inserting an earlier branch shifts `netId/k` to another branch. Hashing parent/history into a repeated-state fingerprint prevents ordinary cycle detection (V1). | Separate storage identity, canonical traversal keys, render-input hash and a geometry-only repetition fingerprint. Specify what semantic equivalence excludes. Treat branch ordinals as ephemeral in v1; remove their stability promise until matching branch identities across edits is designed. |
| N09 | should fix | 6.6, 11.3 | Missing assets and unknown minor-version fields have no safe semantic-edit policy. | A hash does not reconstruct an old built-in symbol. “Report a finding” does not say which bytes to render. An older writer preserving an unknown field cannot know how `renamePart` must rewrite references inside it. | Embed used definitions, or require exact local versions and fail closed if absent. Apply asset updates transactionally with pin remapping and validation. Separate inert extension metadata from required semantic features; refuse edits when reference-bearing features are unknown. Refdes keys remain workable under this restriction. |
| N10 | should fix | 7.3, 8 | The generic-IC/DSL contract still cannot preserve all claimed intent. | Bare pin declarations have no defined numbering, roles or groups; IC pin-side syntax cannot select repeated names by number. `TYPE`, `side-group` and some lexical productions are undefined. JSON label/net-style overrides and much metadata cannot round-trip. | Define generated pin numbers and explicit role/group declarations, numeric selectors, token/comment precedence and strict-priority conflicts. Publish an exact supported conversion subset; reject every unrepresentable field rather than only custom/reserved features. |
| N11 | should fix | 9.2 steps 2, 5; 9.4 | Flow inference, template exceptions and ELK star construction are circular or incomplete. | Feedback is defined using later ranks before rank assignment and may be overridden by patterns matched later. A net star needs edge directions and ordering for passive/bidirectional terminals. Ordinary SPI MOSI/MISO are separate directional signals, not generic bidirectional nets (V2). | Specify an ordered inference procedure and actual serialized block-graph examples for I2C and summing feedback. Keep uncertain bus classification distinct from electrical pin role; add minimal interface-role metadata rather than guessing I2C from any two shared GPIO nets. |
| N12 | should fix | 9.2 step 3 | Power drawing choices still depend on geometry that does not exist yet. | “Short and adjacent” is unknown before placement. A fuse feeding an unnamed net fails the power-path definition unless the downstream net was already classified as power. Include virtual-symbol geometry in reservations. Define the override schema and distinguish supply symbols from signal labels. |
| N13 | should fix | 9.2 step 7, 9.5 | Router and incremental-region mechanics omit necessary state. | A* with bend costs needs arrival direction, and a legal crossing needs straight-through traversal. A dirty set of parts has no contour at which to freeze wire intersections. Removing a part or changing global spacing also lacks a dirty-set rule. | Specify search state, terminal/tree attachment rules, crossing restrictions, bounds, tie order and per-attempt budgets. Define a geometric repair region from pre/post-edit bounds, frozen route fragments and expansion rules. State affected entities for every operation, including removal, hints and global changes. |
| N14 | should fix | 9.5, 10.2, 11.1 | `revision = hash(circuit + intent)` is insufficient for layout-dependent edits and checked fixes. | Canonical relayout or an asset change can alter positions without changing that revision. Define displacement relative to both the original edit targets and the actually expanded dirty set. Do not require hidden part IDs to solve this. |
| N15 | should fix | 10.2-10.3, 11.3 | Setter semantics and convergence guarantees remain incomplete. | Repeating `place`/`align` might append hints; `addHint` is not automatically a setter. ## 4. Over-corrections

- **Phase 0 is too broad.** Start with terminal/verifier counterexamples and three representative layouts, then expand to the twelve-case gate. One candidate plus a baseline can test the pipeline before funding the second ordering implementation. Keep the correctness oracle; defer production packaging and generalized repair machinery.
- **Exact smallest conflict sets are unnecessary.** A deterministic explanatory conflict is enough for an agent. Finding an optimal explanation should not delay routing or placement work.
- **Future schema shapes are premature.** Reject unsupported buses, hierarchy and units by feature code; do not freeze their eventual structures or promise stable route IDs yet. Initial v1 needs version rejection and fixture discipline, not a generalized migration framework before any older version exists.
- **Full undo plus durable fifty-request deduplication is more than a first layout release needs.** Use simple snapshots and a narrowly documented transaction contract initially. If exact retry safety remains a promise, implement N16 rather than calling the sidecar disposable.
- **Two text export modes, both symbol styles and broad module coverage need not all gate Phase 1.** Outlined SVG, one font/style, generic boxes and only the modules needed by the committed corpus suffice. Accessibility descriptions and the net table should remain.
- **Independence should target routing logic, not force duplicate foundations.** The verifier should reconstruct connections independently, but may share audited coordinate types and symbol transforms. Separate copies of geometry mathematics can introduce inconsistent meanings.

## 5. Verified claims

- **V1: Identity/verifier/equivalence counterexamples. Confirmed by a throwaway Node probe**, outside the project, using the written rules rather than an engine implementation. Group/string uniqueness passed while expanded physical membership duplicated pin 14; a dotless T changed endpoint-union behavior after splitting the trunk; hiding a connected endpoint made projected partitions equal; sorted ordinal branch IDs shifted after insertion; 470/4700 resistor variants had equal pin partitions; the expanded resistor envelope contained both its pin and a sample point on the incident wire. The probe also records declaration-order-dependent net allocation. [Script](%TEMP%/schem-revB-probes-2f7ee44cc22d4dbd8b90666a0c9002cd/probe.cjs), [results](%TEMP%/schem-revB-probes-2f7ee44cc22d4dbd8b90666a0c9002cd/results.json). Run `node probe.cjs` there; tested on Windows, Node v24.14.0. These demonstrate missing contracts, not bugs in code that has not been written.
- **V2: I2C versus SPI direction. Partly incorrect in section 9.2.** NXP documents ordinary I2C's bidirectional SDA/SCL and open-drain/open-collector interfaces; Microchip documents MOSI flowing controller-to-peripheral and MISO in the reverse direction. A shared bidirectional SPI variant must be explicit, not the default meaning of MOSI/MISO. Sources: [NXP UM10204, section 3.1.1](https://www.nxp.com/docs/en/user-guide/UM10204.pdf), [Microchip SPI system](https://developerhelp.microchip.com/xwiki/bin/view/products/mcu-mpu/8-bit-avr/structure/spi-interface/). Two shared bidirectional nets alone are insufficient evidence that a circuit implements I2C; that is an inference from the distinction between pin capability and protocol.
- **V3: Embedded SVG font mechanism. Confirmed; “no CSS” needs an exception.** [SVG 2 fonts and glyphs](https://www.w3.org/TR/SVG2/text.html#FontsAndGlyphs) specifies downloadable fonts via CSS Fonts, whose [font-face rule](https://www.w3.org/TR/css-fonts-3/#font-face-rule) supplies font resources. No consumer-application rasterization comparison was performed; universal identical appearance remains unverified.
- **V4: Unmodified MPL libraries need only retained notices. Incomplete.** Mozilla's [MPL FAQ Q7-Q8](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) distinguishes redistributing complete compliant programs from libraries/partial distributions. [MPL 2.0 section 3.2](https://www.mozilla.org/en-US/MPL/2.0/#distribution-of-executable-form) requires covered source availability and information on obtaining it. Keeping notices satisfies this only if they actually provide the required information for the distributed artifact.
- **V5: Real-path checks cover creation and isolate files. Not established.** A separate `fs.realpathSync('not-created.svg')` call in the probe folder returned `ENOENT`. Node's [filesystem documentation](https://nodejs.org/api/fs.html) warns about filesystem check/use races. This supports specifying creation and commit behavior; it does not prove a particular exploit or imply that a trusted local v1 needs a container.
- **V6: Phase 0's stated coverage/dependencies. Checked directly against SPEC.md.** Section 18 F19 says all named low-confidence families appear in Phase 0, but no Sallen-Key case exists. The Phase 0 build list omits findings generation and circuit mutations used by its gates. Cases 11/12 and all specific mutations remain unfixed. Two-week feasibility, timing targets and baseline superiority cannot be verified before measurements.
- **V7: Physical-unit example. Confirmed arithmetically.** At 0.1 inch/G, 48 × 32 G is 4.8 × 3.2 inches, or 121.92 × 81.28 mm; 300 DPI gives 1440 × 960 pixels if those dimensions are the complete export bounds. State explicitly whether the measured dimensions already include margins.

The archived ELK 0.11.1 probe supports only that tested release's direct multi-target-edge rejection, not every elkjs release. Rev B has not selected a dependency version. No new ELK benchmark, cross-platform renderer test or full baseline run was performed for this review.
