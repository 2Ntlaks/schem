# SPEC review

## 1. Verdict

Not ready to build from; ready only for a revised layout spike.
1. Specify the net-to-layout transformation, topology checks, and a constraint-aware placement/routing pipeline before committing to ELK.
2. Separate persistent electrical identity, drawing instances, presentation constraints, and layout history before freezing `schem/1`.
3. Make Phase 0 test difficult circuits and edit stability against explicit gates; six attractive examples cannot validate this architecture.

## 2. Findings

Reviewed all of `SPEC.md` and `schematic-plan.html`. Blockers prevent a reliable implementation contract. Circuit failure cases below are architectural predictions, not results from an implemented schematic engine. V1-V13 refer to the verification list.

Two physical GND pins cannot share one unique name. | Introduce persistent component, unit-instance, and physical-pin IDs; keep reference, number, name, aliases and electrical role separate. | F02 | blocker | 6.3, 9.3, 11.3 | Net identity and membership invariants are missing. | F07 | blocker | 9.2, 12-13 | A wall-clock retry budget cannot guarantee byte-identical output; “no random numbers” does not describe ELK's configurable randomness. | Faster machines can try more candidates and select different results. Test geometry, pixels and encoded bytes separately. |
| F08 | blocker | 9.5 | Interactive layering/crossing minimization is treated as an implementation of exact locks and local re-layout. | Those options influence order; they do not supply the promised freeze boundary or displacement bound. Implement locks as actual constraints. Pin and test the exact ELK options; reserve a routing-only/local solver path. Define how rejected constraints are reported. |
| F09 | blocker | 15, Phase 0 | Six of ten “publishable or one small edit away” can pass using only easy templates. | F10 | should fix | 2 | Prior-art claims are factually overstated. SKiDL draws schematics; netlistsvg has analog support (V9). | F12 | should fix | 6.2-6.5 | No extension model for buses, sheet instances, net classes or wire-level intent. | `DATA[7:0]` needs bit order and bus taps, not a single joined net. | F13 | should fix | 6.4-6.5 | “Later hint wins” conflicts with sorting arrays, strict constraints and compound conflicts. | A right-of B, B right-of C, C right-of A is unsatisfiable without a contradictory pair. | F15 | should fix | 7.1-7.3 | Generic pin sides depend on placement, but placement assumes fixed ports. If D2 and GPIO4 are intended as ESP32-DevKitC aliases, that mapping is wrong (V10). | Separate logical pin inventory from visible pins. Precompute bounded box/port configurations and select consistently. Always surface missing required supplies. | F16 | should fix | 8 | The grammar does not define its tokens or most hint productions; it excludes blank lines used in its own example. Optional `NAME` overlaps `PINREF` unless lexically distinguished. | `net U1.OUT R1.1`, `part D1 led color=red`, `pins:`, comments after values, `+12V`, CRLF and a final line without newline all invite inconsistent parsing. There is no `nc` or `strict` syntax. | Publish lexical rules and complete productions, including quoting/escapes, Unicode, separators, empty lines, EOF and precedence between positional values/options. Make named nets syntactically explicit or constrain names unambiguously. Add valid/invalid examples with exact spans and error codes. |
| F17 | should fix | 8, 6.5 | “Lossless” JSON/DSL conversion is not defined and the DSL cannot express all project fields. Chain endpoints and pin order are underspecified. | Comments, metadata, custom definitions, layout and future extensions can disappear. `chain R1 -> R2` has undefined outside terminals; battery/polarized aliases need an explicit ordering. Repeating net/chain statements may silently merge named nets. | Promise semantic round-trip only for a documented DSL subset, or preserve a concrete syntax tree/extension payload. Reject unsupported reverse conversions. Define chain entry/exit pins per symbol, endpoint behavior, and repeated/conflicting connection semantics. |
| F18 | should fix | 8, 6.2 | Quantity parsing lacks a type-dependent contract. | Bare `4700` means ohms only for a resistor. `M` versus `m`, `u`/`µ`/`μ`, decimal commas, quoted labels and LED `red` can be normalized incorrectly. | Preserve raw values; parse against a per-property quantity/unit schema. Specify case, locale and accepted engineering notation. Separate labels/colors from quantities and never silently reinterpret an ambiguous token. |
| F19 | should fix | 9.2, 9.4 | Left-to-right ranking and the listed templates do not cover several small analog topologies. | An H-bridge needs two vertical legs and a central load, not signal ranks. A differential pair/current mirror needs matched alignment. A Sallen-Key filter or oscillator contains coupled feedback loops that simple op-amp templates do not capture. Arbitrary cycle breaking can stretch returns around unrelated parts. | Benchmark these explicitly. Use topology-aware regions with symmetry, alignment and feedback corridors, then layer only the graph between regions. Use constrained placement/compaction inside ambiguous regions; retain a deterministic fallback. Do not claim crossings are inevitable without testing a specified mapping. |
| F20 | should fix | 9.2 steps 1-2 | Power-port replacement is decided using wire length/crossings before routing, and can erase the topology needed by classification. | Removing a rail can detach a pull-up or every decoupler from its intended IC. Same-net capacitors do not identify which IC they serve. Buck converters, rectifiers, isolated supplies and AGND/DGND need visible power paths/domain distinctions. | Retain the full semantic graph for inference. Add per-connection wire/port overrides, power domains and an optional `decouples` relationship. Evaluate explicit-wire versus port candidates with stable thresholds; penalize unnecessary label hunting and keep important current paths visible. The “most crossings” claim needs measurement (V13). |
| F21 | should fix | 9.4 | Pattern matching lacks overlap resolution, boundary contracts and geometry feasibility. | A transistor bias divider can match both divider and amplifier templates; every capacitor across a common rail can match decoupling. A literal bridge diamond with diagonal symbols conflicts with only 90-degree rotations and orthogonal wires. | Specify matcher predicates, ownership, nesting/priority, boundary terminals, reserved bounds and template versioning. Support composite matches or reject ambiguity. Choose an orthogonal bridge convention or explicitly extend the geometry model. Define “textbook arrangement” as actual constraints. |
| F22 | should fix | 10.1 | A tunable weighted score is neither a correctness gate nor a convergence objective. | Hiding every net behind labels can improve crossings/length while making tracing worse. One hard violation can be outweighed by compactness. A scalar change score hides a flipped symbol or wholesale rerouting. | Rank validity first, then conventions/readability, then aesthetics. Define normalization and counting rules for crossings, shared trunks and bends. Report displacement after translation alignment, rotations, route changes and changed entity IDs. Add a stopping rule and repeated-state detection. |
| F23 | should fix | 10.2 | Suggested repairs are not executable as specified: `swap-pins ... side` is absent from the operation list and could be mistaken for rewiring SDA/SCL. | The agent guesses syntax or changes circuit meaning to improve appearance. Validate candidate repairs in a dry run and report expected metric deltas plus conflicts, or state that no local repair was found. |
| F24 | should fix | 11.1-11.2 | File paths and user symbols/themes have no trust boundary or resource limits. | A tool can overwrite unrelated files; Windows junctions can escape an allowed root. Unescaped labels/custom SVG can inject active markup. Large pin lists, fonts, path data or PNG sizes can exhaust memory. | Restrict canonical input/output paths to configured roots, including symlink/junction handling; default to no overwrite. Escape XML and allowlist primitives, disallow external resources/scripts, and cap parsing/layout/raster workloads. Define cancellation and stdio behavior; add authentication/origin checks if HTTP is introduced. MCP itself is not filesystem isolation (V12). |
| F25 | should fix | 11.2 | Tool responses lack revision/status schemas, filtering, pagination and a compact way to inspect nets or routing problems. | Returning every warning and pin after each edit wastes tokens; a 1024-pixel overview can make labels unreadable. Automatic images on score drops make response cost unpredictable. | Return revision, validity, added/resolved finding IDs, top actionable findings and an optional cursor. Add net/region queries, detail levels and bounded component search results. Make previews explicit or client-configurable; allow finding-targeted crops. Separate successful export from layout/electrical warnings. |
| F26 | should fix | 11.3 | Atomic operations do not define concurrency, retry behavior or persistence of presentation edits. | Retrying `flip` toggles back; `rotate 90` might be relative or absolute; repeated `spacing 1.2` may grow forever. Another agent can overwrite edits. `label`/`pinSides` may be lost on relayout. | Add expected-revision checks, operation IDs, dry-run and rollback/restore. Prefer idempotent setters for orientation, flip and spacing. Define each operation's authoritative target and merge semantics; supply rename-net/ref, set/clear-NC, replace/remove-hint and clear-override operations. Commit circuit plus validated layout transactionally. |
| F27 | should fix | 12.1-12.3 | Bundling one font does not make independently measured text match SVG `<text>` in other applications. Pixel determinism is not encoded-file determinism (V5-V6). | Font fallback, missing glyphs, shaping, kerning and browser/Word substitution change labels and collision bounds. Outlined text loses selection/search unless semantic text is retained separately. | Pin font bytes and shaping settings; disable system font discovery for deterministic rasterization. Use the same glyph positions for measurement and drawing. Define portable outlined and accessible text export modes, supported scripts/fallbacks, and a real consumer-app test matrix. Do not promise identical display merely from inline attributes. |
| F28 | should fix | 12.3 | DPI, scale, physical size and PDF implementation are unspecified. | “300 DPI” cannot determine both pixel count and printed size. Vector PDF needs a separate backend and font/metadata policy; resvg-js's documented output is PNG (V6). Changing themes can invalidate geometry through different text/stroke bounds. | Define physical units and precedence of size/scale/DPI, including PNG resolution metadata. Select and test a vector PDF path, deterministic timestamps/IDs and font handling. Treat theme changes as layout inputs and include margins/stroke extents in export bounds. |
| F29 | should fix | 13 | Goldens and a tuned corpus can certify consistent mistakes; random valid nets cannot guarantee feasible locked layouts. Part count alone is a weak workload bound. | A 30-part design with hundreds of pins or long labels can exceed the time target. The agent could get a prettier but electrically different result, and unconstrained random cases do not exercise real motifs. | Add independent topology checks and edit-sequence/metamorphic tests: alias normalization, input reordering, save/reload, no-op render, add/remove and conflicting locks. Separate training/tuning and held-out circuits. Record hardware, cold/warm timings, pin/edge counts and percentiles. Require reference-netlist equivalence in agent evaluation. |
| F30 | should fix | 14 | Dependency/asset licensing is incomplete, and “public standards” is not permission to redistribute standards artwork. | EPL dependency use can coexist with MIT/Apache project code but retains distribution obligations. resvg-js is MPL-2.0. The verified GPL repositories do not establish the hosted editor's license (V6-V8, V11). | Choose the project license and document dependency notices/source availability, generated-output rights, font embedding and symbol provenance. | F31 | should fix | 15 | Edit stability and edit operations are scheduled after Phase 1 promises a deterministic layout/file model; Phase 1 also attempts the entire symbol/template catalog. | Discovering that locks or local repairs require a different placer in Phase 2 forces redesign. “One small edit” in Phase 0 cannot be evaluated without edit semantics. | Pull minimal edits, topology validation, stability probes and a scripted agent-like repair loop into Phase 0/early Phase 1. A clean source checkout does not test the distributed package. | Test the packed CLI/MCP artifact on a clean Windows machine, including x64/ARM64 targets claimed by dependencies (V6), offline assets, interrupted saves and watch-loop suppression. Keep protocol output on stdout and diagnostics on stderr. Test browser/core parity separately. |
| F33 | suggestion | 9.2 | Alternative approaches are named without a comparison experiment or their costs. | A different algorithm name does not supply analog conventions or reliable routing. | Compare region templates plus ELK against discrete constrained placement/compaction for small regions: stronger symmetry/locks, but more modeling and potentially higher search cost. ## 3. Verified claims

Checked 2026-10-22. Documentation checks establish advertised capabilities, not the proposed engine's quality or performance.

- **V1: ELK fixed ports and ranks. Partly confirmed.** `FIXED_SIDE` fixes a side; `FIXED_POS` fixes the exact local port position. Layered orthogonal routing supports port constraints. The ordinary `layerConstraint` enum offers first/last variants, not arbitrary rows/columns. The spec must identify the adapter for its ranks and hints. Sources: [port constraint definitions](https://raw.githubusercontent.com/eclipse/elk/master/plugins/org.eclipse.elk.core/src/org/eclipse/elk/core/options/PortConstraints.java), [Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html), [layer constraints](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-layering-layerConstraint.html).
- **V2: Interactive layout guarantees stable placement. Only the weaker capability is confirmed.** Both [interactive layering](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-layering-strategy.html) and [interactive crossing minimization](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-crossingMinimization-strategy.html) exist. ELK's [constraint guide](https://eclipse.dev/elk/blog/posts/2023/23-01-09-constraining-the-model.html) explains pseudo positions and additional constraint processing. In experiment E1, interactive cycle breaking/layering plus semi-interactive crossing minimization moved A/B from `(100,100)/(300,100)` to `(12,12)/(72,12)` while preserving local ports. This disproves equating those settings with fixed coordinates; it is not a test of every ELK configuration.
- **V3: Net hyperedges can be passed straight to ELK. Not supported by E1.** One edge with source A and targets B/C failed with `Passed edge is not 'simple'` in elkjs 0.11.1. ELK's [JSON documentation](https://eclipse.dev/elk/documentation/tooldevelopers/graphdatastructure/jsonformat.html) explicitly distinguishes format support from algorithm support. It also says callers must supply measured label sizes. This does not rule out decomposed/shared-trunk routing.
- **V4: The pipeline uses no randomness. Incorrect as an unqualified dependency claim.** ELK exposes a [random seed](https://eclipse.dev/elk/reference/options/org-eclipse-elk-randomSeed.html); zero permits a time-derived seed. Explicit deterministic configuration is necessary. The spec's wall-clock fallback contradiction follows directly from selecting among however many candidates finish in time.
- **V5: resvg determinism across operating systems. Confirmed for the documented pixel claim, not independently reproduced here.** The [resvg README, Reproducibility](https://github.com/linebender/resvg#reproducibility) explicitly claims equal pixels across supported platforms. It does not establish identical encoded PNG/PDF bytes for this tool, differing font inputs or dependency versions. No macOS/Linux rendering experiment was performed.
- **V6: resvg-js packaging/fonts/output/license. Confirmed with limits.** Its [README](https://github.com/thx/resvg-js) documents PNG conversion, native prebuilds, Windows x64/x32/ARM64, a WASM backend, explicit fonts and `loadSystemFonts: false`. It declares MPL-2.0. This is documentation verification, not a clean-install or PDF-backend test.
- **V7: EPL-2.0 with MIT/Apache-2.0. Compatible for separately authored dependent code, with retained obligations.** The installed elkjs 0.11.1 manifest declares EPL-2.0. [EPL text, sections 1 and 3](https://opensource.org/license/EPL-2.0) excludes specified linking/interface-only work from Modified Works and requires source availability and notices when distributing the covered Program. Therefore independently authored application code can retain MIT/Apache terms; elkjs does not become MIT/Apache and “unmodified” does not remove redistribution duties. Exact bundled distribution compliance remains to be specified.
- **V8: Circuit Diagram GPL-2.0. Confirmed for identified repositories.** The official site's [source links](https://www.circuit-diagram.org/) lead to the application and components repositories; their [application license](https://github.com/circuitdiagram/circuitdiagram/blob/master/LICENSE.txt) and [component license](https://github.com/circuitdiagram/components/blob/master/LICENSE.txt) are GPL v2. The application README identifies its contents as CLI/utilities and points elsewhere for the web editor. I did not verify the hosted editor's implementation license. The spec's blanket legal conclusion about any copying exceeds this evidence; keep its no-copy decision without treating license labels as a complete derivative-work analysis.
- **V9: SKiDL draws nothing; netlistsvg is only digital. Incorrect/overstated.** SKiDL documents [SVG and KiCad schematic generation](https://devbisme.github.io/skidl/#generating-a-schematic), including automatic placement/routing. netlistsvg documents an [analog example and analog skin](https://github.com/nturley/netlistsvg). Their achieved quality on this corpus was not measured. The broader “nothing on the market” claim remains unverified.
- **V10: Module aliases are interchangeable. Not generally true.** Espressif's [DevKitC V4 header table](https://docs.espressif.com/projects/esp-idf/en/v5.0.4/esp32/hw-reference/esp32/get-started-devkitc.html#header-block) maps D2 to GPIO9; IO4 maps to GPIO4. If section 7.3 intends D2 and GPIO4 as synonyms for that board, it is incorrect. The table also demonstrates repeated GND pins and variant-dependent availability.
- **V11: Standards provide unrestricted reusable artwork. Not established.** IEC's [copyright terms](https://webstore.iec.ch/en/copyright) cover its publications and database content and distinguish permitted use from database replication. This does not prove independently drawn conventional symbols are prohibited; it does mean public standards are not automatically public-domain asset libraries. IEEE 315 artwork redistribution rights were not independently verified.
- **V12: MCP/file-path safety. No automatic isolation guarantee.** The official [local server security guidance](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/tutorials/security/local-server-security.mdx) distinguishes cooperative path allowlists from enforced process isolation. File roots and validation must be implemented and tested by this product.
- **V13: Layout quality/performance claims. Unverified.** Neither the “most crossings” power-port claim nor the latency/hand-drafted-quality targets have supporting measurements in the supplied files. For the proposed complementary router, ELK documents [libavoid routing without moving nodes](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-alg-libavoid.html) and a [separate native integration](https://eclipse.dev/elk/blog/posts/2022/22-11-17-libavoid.html); this is not evidence that it ships in elkjs.

**Experiment E1:** Windows x64, Node v24.14.0, elkjs 0.11.1 installed with scripts disabled outside the project. Two 40x40 nodes had fixed zero-size east/west ports at `(40,20)` and `(0,20)`, RIGHT direction, ORTHOGONAL routing, seed 1 and the four interactive options from the ELK guide. A separate three-node case tested a multi-target edge. Reproduce with `node probe.cjs` in the retained [temporary experiment folder](C:/Users/ntlak/AppData/Local/Temp/schem-spec-review-bc753516c60f411f816dcd5c642ca51c); [script](C:/Users/ntlak/AppData/Local/Temp/schem-spec-review-bc753516c60f411f816dcd5c642ca51c/probe.cjs), [results](C:/Users/ntlak/AppData/Local/Temp/schem-spec-review-bc753516c60f411f816dcd5c642ca51c/result.json), and package lock are retained there. A follow-up attempt to install 0.13.0, seen in upstream `master` metadata, returned npm `ETARGET`; no results are claimed for that version. No project code was written.

## 4. Open questions for the author

1. Which difficult circuit families must v1 handle automatically, and which may return an explicit unsupported/low-confidence result?
2. Does “same input” include previous layout and edit history? Must two independently edited but electrically identical projects converge to the same drawing?
3. Are these logical schematics or physical wiring instructions? Must repeated physical terminals, package pin numbers and board revisions remain distinguishable?
4. May the engine replace signal wires with labels automatically, and what limit prevents a superficially tidy but untraceable drawing?
5. On infeasible locks or exhausted search, should edits roll back, save an invalid draft, or preserve the last valid layout? Which exports are allowed?
6. What exact operations count as “one small edit,” and who scores held-out cases without knowing which algorithm produced them?
7. What printed dimensions, supported languages, consumer applications and Windows installation targets form the first release contract?
